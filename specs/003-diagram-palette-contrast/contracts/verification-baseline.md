# 契约：验收基线（夹具令牌与对比度断言）

本文件规定"检查凭什么算通过"。核心教训：现有 325 项检查在**编造的令牌**上全绿，而真实宿主下的连边只有 1.25:1——基线失真时，检查数量再多也不证明可用。

## 1. 令牌基线

- 唯一来源：`verify/host-tokens.json`，内容形如

```json
{
  "source": "/Applications/DeepSeek Harness.app/Contents/Resources/app.asar",
  "version": "0.2.2-rc.5",
  "extracted_at": "2026-11-26",
  "light": { "--dsw-alias-border-l2": "rgba(0,0,0,0.1)", "…": "…" },
  "dark": { "--dsw-alias-border-l2": "rgba(255,255,255,0.12)", "…": "…" }
}
```

- `verify/harness/index.html` 的 light/dark 令牌块、`scripts/build-preview.mjs` 的预览块，**都必须**由这份快照生成（或逐字复制并附生成命令）。
- `verify/check-bundle.mjs` 断言：夹具里出现的每个 `--dsw-*` 变量与值，都必须能在快照里找到同值；不得出现快照之外的自造值。
- 宿主升级后刷新快照的步骤写在 [quickstart.md](../quickstart.md)，刷新后必须重跑全套检查。

## 2. 夹具里的 dark 作用域

夹具用 `body[data-ds-dark-theme]` 模拟深色**仅限测试文件内**；插件源码里出现任何 `data-ds-dark-theme` 都算违规（`check-bundle.mjs` 断言）。

## 3. 断言清单

| 组 | 断言 | 门槛 | 覆盖需求 |
| --- | --- | --- | --- |
| A 结构可见 | flowchart 连边 `stroke` 对画布背景的对比度，浅色与深色各一次 | ≥3:1 | FR-001、FR-002 |
| A 结构可见 | 未分类形状（`rect` 无角色时）描边对背景 | ≥3:1 | FR-002 |
| B 文字可读 | 五类角色节点内 `text` 对自身填充的对比度 | ≥7:1 | FR-003 |
| C 角色成色 | 五个角色的填充两两互异 | 全不相等 | FR-004、FR-012 |
| C 角色成色 | 四个彩色角色的填充彩色通道差（max−min），及相邻角色对色相差 | ≥20 / ≥20° | FR-004、SC-003 |
| C 角色成色 | "处理"类（非彩色角色）填充与画布背景的对比度、描边对背景 | >1.05 / ≥3:1（不是"白底白框"） | FR-002、FR-012 |

## 4. 计分口径

- `verify/run-harness.mjs` 的 `EXPECTED_CHECKS` 必须与实际检查数**逐字相等**：新增断言时同步改数字，不允许"至少"。
- 允许断言的容差：对比度比较允许 `±0.05` 的浮点误差；颜色相等比较按 `getComputedStyle` 返回的字符串逐字比较（`rgb()` 归一化后）。
- 任何一项失败即整体失败，不允许"警告但不退出非零"。
- 负向自检（G）必须单独计数并输出 `assertion has teeth` 一行，便于人读日志时确认。

## 5. 不可用假令牌替代的场次

以下三类必须在真实令牌下取证，缺一即视为未验证：

1. 浅色与深色各一张会话内截图（flowchart + 一张多类别图）。
2. 作者 `classDef` 的图（证明行内样式仍优先）。
3. 360px 视口与 200% 字体下的同一张图（证明改颜色没破坏窄屏契约）。
