# 需求质量 Checklist: 图在真实宿主主题下看得清、有颜色分辨度

**Purpose**: 在进入计划阶段前，检查本 feature 的规格是否"描述清楚、可验证、不夹带实现细节"，重点覆盖三项硬约束：对比度可量测、颜色只来自宿主、验收证据可用。
**Created**: 2026-11-26
**Feature**: [spec.md](../spec.md)

**Note**: 本清单是评审者持有的需求质量产物，不代表实现进度。
**Review Ownership**: 只有评审者确认某条需求质量准则已被满足时，才可标记 `[x]`。
**Marker Semantics**: `[x]` 表示"该准则已被评审并满足"，不表示代码已完成。

## 内容质量

- [ ] CHK001 规格只描述"读者看到什么、测得什么"，未规定具体 CSS 变量名、文件路径或函数名。
- [ ] CHK002 每一项功能需求都能对应到至少一个用户场景或边界情形。
- [ ] CHK003 背景中的调查结论与需求之间没有矛盾（尤其是"主因在渲染侧"与 FR 的一致性）。
- [ ] CHK004 术语统一：结构线、节点填充、分类色、画布背景在全文各处含义一致。

## 需求完整性

- [ ] CHK005 浅色与深色两个主题都被明确要求，而不是只要求其中一个。
- [ ] CHK006 作者显式指定颜色（`classDef`/`style`）与插件色板的优先级已明确。
- [ ] CHK007 宿主令牌缺失/改名时的回退行为已明确，且回退目标本身可读。
- [ ] CHK008 已有可观测行为（缩放、拖动、卸载回退、窄屏滚动）被显式列为不变项。
- [ ] CHK009 分类色板的最低数量与可区分判据已给出。
- [ ] CHK010 原先的三项 `[NEEDS CLARIFICATION]` 已由读者拍板并写进 FR/SC，规格中不再残留待定标记。

## 需求可验证性

- [ ] CHK011 每条对比度要求都带数值阈值（3:1 / 4.5:1），可以被脚本量测而非靠主观判断。
- [ ] CHK012 成功标准全部可量测，且能说明"如何测"（真实令牌渲染 + 量测）。
- [ ] CHK013 存在一条能证明"验收证据链已修好"的标准（旧配色下新检查会失败）。
- [ ] CHK014 验收场景覆盖了"无颜色指令的普通图"这一最主要场景，而不是只测作者特意上色的图。

## 就绪度

- [ ] CHK015 没有实现细节泄漏（不指定具体哪个宿主令牌、不用 `color-mix` 等实现手段作为需求）。
- [ ] CHK016 没有未定义的缩写或上下文缺失的表述（读者无需读代码即可理解）。
- [ ] CHK017 三个澄清项已在规格中就地标记，而不是散落在文末备注。
- [ ] CHK018 与 Constitution v2.0.0 的五项原则无冲突（特别是"颜色取自宿主主题变量"与"降级不丢数据"）。
- [ ] CHK019 "颜色按节点角色分配"这一决策附带可解释性要求：读者能知道颜色含义来自图形角色，而不是作者意图。
- [ ] CHK020 模型侧那一条能力说明被限定为"说明能力"，未越界改动"何时用图"的偏好语义。
